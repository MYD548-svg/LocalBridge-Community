## 2. 集成链路

ChatGPT 顶层网页 → 内容适配器 → 扩展后台 → Native Messaging 宿主 → 同目录 MCP 适配器 → 当前用户命名管道 → 现有 MCP 权限层与工具引擎。

新增 localbridge-browser-host.exe 随安装程序交付，固定启动同目录的 localbridge-mcp.exe；用户主动点击连接时可启动同目录主程序。扩展不访问新增 HTTP/WebSocket 服务。现有内部 HTTP 通道和客户端权限契约继续由应用管理。

网页和 Codex 都使用本地运行通道；浏览器状态、授权及统计独立，不将网页做成第三种互斥运行模式，不改动用户 Codex 配置。首版绑定当前活动工作区，不同时授权多个不同工作区。

## 3. 普通用户的默认操作

1. 安装同一候选提交产生的 LocalBridge 安装包，启动本地服务并选择工作区。
2. 从 GitHub 下载该候选的扩展 ZIP。当前候选保存在 Actions 产物中；正式发布前不会创建 Release。应用的下载按钮是长期发行页入口，候选需要从对应提交的产物获取。
3. 在“ChatGPT 网页”卡片选择 ZIP 或已解压目录，确认已停止工具并关闭扩展，点击导入。应用核验后准备到 %LOCALAPPDATA%\LocalBridge\browser-extension\current。
4. 复制 edge://extensions（或 chrome://extensions）到浏览器地址栏，开启开发者模式，选择“加载解压缩的扩展”，使用应用提供的固定目录。ZIP 中含编译产物，无需编译。
5. 打开或刷新 ChatGPT，点击扩展图标连接；在 LocalBridge 核对浏览器实例、工作区和权限并批准配对，然后在扩展为当前聊天启用工具。
6. 选择工具，填入说明，并在 ChatGPT 手动发送。仅将启用之后完成的新助手消息生成执行候选。
7. 在扩展自身窗口查看工具与参数并确认执行。实际结果需要另一次点击才能填入草稿，再由用户在 ChatGPT 点击发送。

“文件已准备”“浏览器已连接”“聊天已启用”“真实调用成功”分别统计。注册表存在、文件存在或模拟结果都不等同于真实工具成功。临时新聊天生成持久聊天地址时，或切换聊天、刷新页面后，需要重新启用；旧结果可在原聊天查看和复制。

结果会进入在线聊天。有草稿、页面结构不兼容、消息或参数发生变化、模型仍在输出、填入状态无法确认时暂停，保留结果供手动复制。首版不自动发送或执行，不支持其他聊天网站、图片附件上传或复杂 MCP Apps 界面。

## 4. 身份、授权及请求状态

发行版公钥固定，扩展 ID 为 fflooodpohkmlllmfgajdjabidofmopb，宿主名为 com.localbridge.chatgpt_web。开发版使用另一公钥、ID、宿主名、输出目录及应用构建特性，不能接入正式应用。没有保存签名私钥，manifest 公钥用于保持加载身份。

控制管道沿用当前用户 SID、对端进程与安装目录内可执行文件核验。主程序保存独立版本化配对和请求记录。配对批准带上界面显示的工作区身份与权限摘要，阻止显示范围变化后的误批准。

主程序签发三十秒、单次使用的内部授权；经宿主与适配器 prelude 交给权限层初始化并绑定 MCP 会话。模型参数和 clientInfo 不是授权凭据。之后继续检查实际授权、工作区和权限；撤销、权限变化、工作区切换或服务停止使旧授权失效，切回原目录也不会恢复。

每个聊天独立 MCP 会话，最多四个浏览器会话；同一浏览器实例的同一聊天不能同时拥有两条会话，每聊天同时一个工具请求。异常退出、初始化失败与主动断开释放授权；主程序退出关闭控制管道。用户停止服务后不会后台循环重启。

请求按浏览器实例、工作区、聊天、分支、助手消息、工具序号和规范化参数摘要落盘去重。先记录再执行；重复返回已有结果或状态。未完成请求在恢复后标记结果未知，不自动重放，不把前端去重宣称为 exactly-once。

外层协议独立版本 1，MCP JSON-RPC 身份、错误、通知、取消、structuredContent 和输出引用保留。每帧最多 256 KiB，原始分片 180 KiB；请求最多 4 MiB，响应最多 16 MiB，重组最多四组、十五秒、32 MiB 总预算。网页填入结果超过 32 KiB 时提供输出引用和缩小读取范围的提示，完整记录在本机保存。

## 5. 扩展包导入、升级及安装

ZIP 包含编译后的 content/background/popup、manifest、版本/协议/兼容信息、逐文件 SHA-256 和中文图解。拒绝错误身份、协议、权限、缺少入口、哈希不符、Windows 不安全路径/大小写别名、链接及特殊文件、超过 32 MiB 或 64 个受管理文件的包。哈希用于核验一致性，不是发布者签名。

更新始终使用固定加载目录，先备份全部受管理文件，逐个明确路径原子替换，最后更新 manifest 与元信息。未知用户文件保留；失败恢复旧版本；导入中断的事务在下一次导入时先恢复，再处理新包。所有备份、测试夹具和旧构建目录保留，不批量删除。用户需关闭扩展、导入新版、重新启用并重新加载，随后刷新 ChatGPT。

宿主采用独立 browser-host 构建特性，阶段成功证据包含当前源码 SHA、二进制/模板哈希、协议及固定 ID；失败先失效旧证据。安装器将宿主和适配器放在主程序同目录，生成绝对路径 manifest，并写入 Edge/Chrome 的 HKLM 32/64 位注册位置。升级占用时停止安装并提示关闭扩展和应用后重试，不强制杀死其他程序。存在其他安装的注册项时停止，不夺取注册；卸载只删除仍指向本安装的确切注册项及本安装生成的 manifest。

## 7. 一轮 CI 的安排

保留现有十九个阶段和单个 Windows 作业，不新增单独扩展工作流：

- frontend-test/build：桌面与扩展测试、类型检查、生产构建、发行 ZIP；
- runtime-resources：显式编译/lint 宿主特性并生成当前 SHA 证据；
- rust-test/clippy：授权、撤销、容量、持久去重、导入恢复、分片，以及新宿主进程和实际 Windows 管道测试；
- nsis-package：主程序、宿主、适配器、清单模板及固定注册；
- package-integrity：打开安装 EXE，核验新增文件及哈希，拒绝重复资源覆盖；
- artifacts：同一源码 SHA 的安装 EXE、扩展 ZIP、中文指引、校验和来源报告；失败保留诊断。

Community 工作流仅更新收集项，保留原 main、release/*、标签及 PR 触发条件。无 PR 的普通 codex/ 分支预期只触发一轮 CI、一个 Windows 作业。这轮仅产生候选产物；云端结果本次为 UNVERIFIED。
